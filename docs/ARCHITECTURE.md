# Архитектура

## Граница системы

Это отдельный клиентский React/Vite-проект без backend, базы данных, авторизации и загрузки файлов через публичный сайт.

```text
локальный ПФХД.xlsx + локальная выгрузка договоров.xlsx
  → tools/update_dashboard.py
  → проверка схемы, сумм, кодов, дублей и приватности
  → public/data/*.json (только агрегаты)
  → React/Vite → GitHub Pages
```

ФИО и номера договоров существуют только во время локальной обработки. Номер договора используется для дедупликации, нормализованное ФИО — для подсчёта уникальных людей. Ни исходные значения, ни их хеши не входят в публичные файлы.

## Публичные данные

- `plan.json` — статичная база ПФХД и маркетингового плана;
- `current.json` — последний полностью проверенный срез;
- `snapshots/YYYY-MM-DD.json` — агрегированный снимок дня;
- `history.json` — одна точка на календарную дату.

`current.json` содержит агрегированные сегменты по уровню, форме, направлению, факультету, гражданству, скидке, приоритету и статусам. Для точного числа уникальных людей при комбинированных фильтрах публикуется куб только с числовыми результатами запросов. Идентификаторов людей в кубе нет.

Все файлы сначала формируются во временной директории, проверяются и только затем атомарно заменяют действующий срез.

## Договоры и платежи

Полный факт оплаты — сумма всех детальных строк выгрузки. Итоговая строка Excel используется только как контроль и не складывается второй раз. Параллельно публикуется сумма после удаления точных дублей договоров. Портфель считается по уникальным договорам со статусом `Подписан` и сумме первого семестра после скидки.

Прежний операционный срез сохраняется в сверке: приоритет 1, без отозванных заявлений и отменённых договоров, без точных дублей.

## План и совместные программы

Плановая запись: `level + form + code + directionName + facultyScopes[]`. Совместная программа хранится один раз. В университетском итоге план считается один раз; в фильтре факультета программа доступна каждому участнику без искусственного деления цели.
