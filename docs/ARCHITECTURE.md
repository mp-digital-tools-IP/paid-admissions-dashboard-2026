# Архитектура

## Граница системы

Это отдельный клиентский React/Vite-проект. Он не зависит от существующего дашборда приёмной кампании, не имеет backend, базы данных, авторизации или загрузки файлов через публичный сайт.

```text
локальный ПФХД.xlsx + локальная выгрузка договоров.xlsx
  → tools/update_dashboard.py
  → проверка схемы, формул, кодов, дублей и приватности
  → public/data/*.json (только агрегаты)
  → React/Vite
  → GitHub Pages
```

Исходные Excel и строковые идентификаторы договоров существуют только во время локальной обработки. Дедупликация выполняется по номеру договора в памяти; номер не входит ни в одну публичную структуру.

## Публичные данные

- `plan.json` — неизменная база плановых записей;
- `current.json` — последний полностью проверенный срез;
- `snapshots/YYYY-MM-DD.json` — проверенный агрегат дня;
- `history.json` — по одной точке на календарную дату.

Публикация реализована как атомарная замена: все четыре файла сначала создаются и проверяются во временной директории. При ошибке публичные файлы восстанавливаются.

## Идентичность направления

Плановая запись: `level + form + code + directionName + facultyScopes[]`. Совместная программа хранится один раз. Университетский итог считает её один раз, а UI выводит отдельный блок «Совместные программы»; в фильтре факультета программа остаётся видимой для каждого участника без искусственного деления плана.
